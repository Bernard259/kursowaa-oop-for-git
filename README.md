# КУРСОВОЙ ПРОЕКТ: Tetris (C++ / WinAPI / консоль)

Этот проект — учебная реализация игры **Тетрис** на C++ для Windows с вводом в реальном времени через WinAPI и выводом в консоль без заметного мерцания.

## 1) Кратко о проекте

- Язык: `C++17`
- Платформа: `Windows`
- Ввод: `GetAsyncKeyState` (через `KeyScanner`)
- Рендер: **по умолчанию** цветной вывод в консоль через ANSI-коды (`ColorRenderer` в `main.cpp`); альтернатива — ASCII с буфером кадра (`ScreenBuffer`). Оба класса реализуют общий интерфейс `IRenderer`.
- Поле: `10 x 20`
- Игровой цикл: около `60 FPS` (`Sleep(16)`)
- Механики: движение, поворот, soft/hard drop, hold, ghost, уровни, очки, комбо, **локальный рекорд** (отображается в HUD во время игры и сохраняется в `highscore.txt` при новом максимуме), пауза, рестарт, Game Over

> **Запуск:** соберите и запускайте `tetris.exe` из **корня проекта**, чтобы файл рекорда `highscore.txt` создавался рядом с исполняемым файлом (это служебное сохранение; в игре показатель выводится на экран в строке статистики).

## 2) Управление

- `A` — влево
- `D` — вправо
- `S` — мягкое падение (Soft Drop)
- `W` — поворот
- `Space` — жесткое падение (Hard Drop)
- `Shift` — Hold
- `P` — пауза
- `R` — рестарт
- `Esc` — выход

## 3) Как собрать и запустить

### Вариант 1 (проще): через bat-файл

1. Откройте `cmd` или `PowerShell` в папке проекта.
2. Выполните:
   - `build.bat`
3. После успешной сборки запустите:
   - `tetris.exe`

При первом побитии прежнего максимума очков в каталоге игры появится файл `highscore.txt` (только число рекорда).

### Вариант 2: вручную через g++

Состав исходников совпадает с `build.bat`. Пример одной командой:

`g++ -std=c++17 -O2 -Wall -Wextra -o tetris.exe src/main.cpp src/GameEngine.cpp src/ColorRenderer.cpp src/ScreenBuffer.cpp src/MovementController.cpp src/LineClearingSystem.cpp src/RuleManager.cpp src/SequenceGenerator.cpp src/KeyScanner.cpp src/CommandMapper.cpp src/GridModel.cpp src/ActivePiece.cpp src/GhostPiece.cpp`

## 4) Архитектура и роли классов

Проект разбит на простые классы с четким разделением ответственности.

- `GameEngine` — главный цикл игры, тайминги, обновление систем
- `RuleManager` — очки, уровни, комбо, локальный рекорд, Game Over, скорость гравитации
- `MovementController` — движение/поворот/дроп/hold/фиксация фигуры
- `KeyScanner` — только считывание клавиатуры через WinAPI
- `CommandMapper` — перевод клавиш в флаги игровых команд
- `ActivePiece` — активная фигура (тип, поворот, координаты)
- `GhostPiece` — позиция «призрака»
- `GridModel` — модель поля `10x20`, хранение закрепленных блоков
- `LineClearingSystem` — очистка полных линий и сдвиг вниз
- `SequenceGenerator` — генератор фигур по системе «мешка» (bag)
- `IRenderer` — абстракция отрисовки кадра (`GameEngine` не зависит от конкретного вывода в консоль)
- `ColorRenderer` — цветной вывод через ANSI-последовательности и VT-режим консоли Windows
- `ScreenBuffer` — сборка ASCII-кадра в буфере и вывод через `WriteConsole` с фиксацией курсора в `(0,0)` для снижения мерцания

## 5) Подробное описание каждого файла

Ниже — назначение **каждого файла проекта**.

### Корень проекта

#### `build.bat`
- Скрипт сборки под MinGW g++.
- Явно перечисляет нужные файлы из папки `src` (включая `ColorRenderer.cpp` и `ScreenBuffer.cpp`).
- Формирует исполняемый файл `tetris.exe`.

#### `README.md`
- Текущая документация проекта.

#### `highscore.txt` (появляется при игре)
- Служебный файл с сохранённым **локальным рекордом** (целое число очков). Создаётся/обновляется автоматически, если запись в каталог игры доступна.
- Не входит в репозиторий обязательно; при отсутствии файла рекорд считается нулевым до первой партии.

### Папка `src/`

#### `main.cpp`
- Точка входа (`main`).
- Создаёт `ColorRenderer`, передаёт его в `GameEngine` как реализацию `IRenderer` и запускает цикл игры.
- Чтобы использовать ASCII-рендер, достаточно подключить `ScreenBuffer` и передать его в `GameEngine` вместо `ColorRenderer` (см. интерфейс `IRenderer`).

---

#### `GameEngine.h`
- Объявление класса `GameEngine`.
- Конструктор принимает указатель на `IRenderer` для отрисовки.
- Хранит все основные подсистемы как поля.
- Описывает приватные методы цикла (`restartRound`, `handleEdgeCommands`).

#### `GameEngine.cpp`
- Реализация главного игрового цикла.
- Логика кадра:
  1) чтение клавиш,
  2) маппинг в команды,
  3) обработка edge-событий (pause/restart/hold/rotate/hard drop),
  4) горизонтальное движение с повтором,
  5) soft drop,
  6) гравитация по таймеру,
  7) отрисовка кадра через указатель на `IRenderer` (полиморфный вызов `renderFrame`).
- Поддерживает `Esc` для выхода.

---

#### `GridModel.h`
- Объявление класса `GridModel`.
- Поле фиксированного размера (`WIDTH = 10`, `HEIGHT = 20`).
- Методы чтения/записи клеток, проверки установки фигуры, слияния фигуры с полем.

#### `GridModel.cpp`
- Реализация хранения сетки `cells[20][10]`.
- Проверка коллизий с границами/занятыми клетками (`canPlaceShape`).
- Копирование блоков фигуры в поле (`mergePiece`).

---

#### `ActivePiece.h`
- Объявление `enum PieceType` (`I, O, T, S, Z, J, L`).
- Объявление класса `ActivePiece`:
  - текущий тип фигуры,
  - текущий поворот,
  - текущая позиция на поле.
- Статические методы для работы с формой фигуры.

#### `ActivePiece.cpp`
- Таблица форм фигур в матрице `4x4` для 4 поворотов.
- Реализация геттеров/сеттеров фигуры.
- Реализация `isBlockAt(...)` для проверки блока в локальной матрице.

---

#### `GhostPiece.h`
- Объявление класса `GhostPiece`.
- Хранит тип/поворот и позицию призрачной проекции.

#### `GhostPiece.cpp`
- Реализация вычисления финальной точки падения активной фигуры.
- Использует `GridModel::canPlaceShape(...)`, двигаясь вниз до упора.

---

#### `SequenceGenerator.h`
- Объявление класса `SequenceGenerator`.
- Хранит «мешок» (`bag`) и позицию в мешке.
- Методы:
  - взять следующую фигуру,
  - посмотреть следующую (preview),
  - сброс генератора.

#### `SequenceGenerator.cpp`
- Реализация bag-system:
  - наполнение мешка всеми 7 фигурами,
  - перемешивание,
  - последовательная выдача.
- При исчерпании мешок формируется заново.

---

#### `KeyScanner.h`
- Объявление класса `KeyScanner`.
- Никакой игровой логики.
- Только хранение текущих состояний нужных клавиш.

#### `KeyScanner.cpp`
- Реализация опроса клавиш через `GetAsyncKeyState`.
- Обновляет флаги нажатий каждый кадр (`refresh`).

---

#### `CommandMapper.h`
- Объявление класса `CommandMapper`.
- Хранит флаги команд: left/right/soft/rotate/hard/hold/pause/restart.

#### `CommandMapper.cpp`
- Преобразует значения из `KeyScanner` в удобные флаги команд.
- Явно связывает клавиши:
  - `A, D, S, W, Space, Shift, P, R`.

---

#### `MovementController.h`
- Объявление класса `MovementController`.
- Основной «оператор фигуры»: перемещения, поворот, hold, lock.
- Хранит ссылки/указатели на связанные подсистемы.

#### `MovementController.cpp`
- Реализация:
  - `tryMoveLeft/Right/Down`,
  - `tryRotateClockwise` (с простыми kick-смещениями),
  - `hardDrop`,
  - `tryHold`,
  - `lockPiece`,
  - `spawnNextPiece`.
- Проверки столкновений проходят через `GridModel`.
- После фиксации запускает очистку линий и спавнит новую фигуру.

---

#### `LineClearingSystem.h`
- Объявление `LineClearingSystem`.
- Интерфейс для поиска/очистки заполненных рядов.

#### `LineClearingSystem.cpp`
- Проверяет ряды на полноту.
- Удаляет полные ряды и сдвигает всё выше стоящее вниз.
- Возвращает число очищенных линий.
- Передаёт результат в `RuleManager`.

---

#### `RuleManager.h`
- Объявление `RuleManager`.
- Хранит:
  - счёт,
  - **локальный рекорд** (`bestScore`),
  - уровень,
  - число очищенных линий,
  - состояние комбо,
  - время партии,
  - флаг `Game Over`.

#### `RuleManager.cpp`
- Реализация начисления очков:
  - 1 линия = 100
  - 2 линии = 300
  - 3 линии = 500
  - 4 линии = 800
- Учитывает множитель уровня.
- Реализует бонус комбо.
- Поднимает уровень каждые 10 линий.
- Вычисляет задержку гравитации по уровню.
- При старте загружает рекорд из `highscore.txt` (если файл есть и корректен); при превышении текущего рекорда обновляет значение и перезаписывает файл. Сброс раунда (`reset`) очки партии не смешивает с сохранённым рекордом.

---

#### `IRenderer.h`
- Абстрактный интерфейс отрисовки одного кадра (`renderFrame(...)`).
- Позволяет `GameEngine` вызывать отрисовку, не зная, используется ли `ColorRenderer` или `ScreenBuffer`.

---

#### `ColorRenderer.h`
- Объявление `ColorRenderer` — реализация `IRenderer` для цветного текстового вывода.

#### `ColorRenderer.cpp`
- Включает в консоли Windows режим виртуального терминала (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`) для поддержки ANSI escape-последовательностей.
- Формирует кадр в `std::string` с управляющими кодами очистки экрана, цветами блоков и рамкой поля.
- В строке статистики отображает **текущий счёт**, **рекорд** (`Рекорд: …`), уровень и время партии.

---

#### `ScreenBuffer.h`
- Объявление `ScreenBuffer`.
- Реализует `IRenderer`: буфер кадра фиксированного размера, методы `renderFrame` и вывод через `presentToConsole()`.

#### `ScreenBuffer.cpp`
- Формирует текстовый ASCII-кадр:
  - заголовок и строка счёта/уровня/линий/времени,
  - локальный рекорд (**«Рекорд: …»**) в строке заголовка справа,
  - рамка поля, закреплённые блоки, активная фигура и призрак (данные интерфейса передаются в `renderFrame`),
  - сообщение паузы при необходимости.
- Выводит кадр в консоль через установку курсора в `(0, 0)` и построчный вывод через `WriteConsoleA`, что уменьшает мерцание.

## 6) Игровые правила в проекте

- Размер поля: `10x20`.
- Фигуры: `I, O, T, S, Z, J, L`.
- Гравитация ускоряется с уровнем.
- Hold доступен 1 раз до фиксации текущей фигуры.
- Генератор очереди фигур — система «мешок» (все 7 типов, перемешивание, выдача по одной).
- Есть ghost-проекция (при цветном рендере отображается на поле).
- Локальный рекорд по очкам отображается в интерфейсе во время игры; максимум сохраняется в `highscore.txt` для следующих запусков.
- Есть пауза и рестарт.
- При невозможности заспавнить новую фигуру — `Game Over`.

## 7) Что важно для защиты курсовой

- Код разбит на небольшие классы и файлы по ролям.
- Каждая система делает одну понятную задачу.
- Ввод, правила, движение и рендер разделены; смена способа вывода иллюстрируется интерфейсом `IRenderer` и двумя реализациями.
- Используются базовые и прозрачные конструкции C++ без излишне сложных абстракций.
